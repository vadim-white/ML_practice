# QA System: Anti-Hallucination Pipeline

## 🎯 Задача
Снизить галлюцинации LLM на валидационной выборке:
- **Консистентность:** На семантически одинаковые вопросы (3 варианта формулировки) — одинаковый ответ
- **Честность:** Если ответа нет в базе знаний — строго `"Не знаю"`, без выдумок

## ⚙️ Как работает

```
Вопрос
   │
   ├─▶ Фильтр провокаций → "Не могу дать точный ответ"
   │
   ├─▶ Поиск в кэше (embedding + keyword match)
   │
   ├─▶ RAG retrieval (exact match по векторной БД)
   │
   ├─▶ LLM генерация (YandexGPT, JSON-формат)
   │
   └─▶ Выбор лучшего ответа:
         • Cosine similarity эмбеддингов
         • LLM-оценка уверенности (0.0–1.0)
         • Порог 0.3 → отсев ненадёжных
```

## 🔑 Ключевые фичи
- **Дедупликация ответов:** Кэширование с нормализацией текста и проверкой перекрытия ключевых слов
- **Мульти-кандидатный подход:** Объединение ответов из кэша, RAG и LLM
- **Самооценка уверенности:** LLM ранжирует варианты ответов перед финальным выбором
- **Жёсткий формат вывода:** Только JSON-массив, парсинг с обработкой ошибок

## 🛠️ Стек
- **LLM:** `yandexgpt-5-lite-8b-instruct` (llama.cpp, GGUF Q4)
- **Embeddings:** локальная модель через `rag_utils_gpu`
- **RAG:** векторный поиск + мета-фильтрация
- **Python:** `numpy`, `torch`, `re`, `json`

## 📁 Структура
```
project/
├── solution.py                 # Основной пайплайн
├── rag_utils_gpu.py        # RAG + эмбеддинги
├── input.json / output.json # Вход/выход
└── *.gguf                  # Модель LLM
```

## 🚀 Запуск
```bash
python solution.py  # Читает input.json → пишет output.json
```

> **Примечание:** Требуется локально размещённая модель `yandexgpt-5-lite-8b-instruct-q4_k_m.gguf` и инициализированный RAG-индекс.
